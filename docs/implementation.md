# Implementation and reproduction

The repository contains one shared implementation tree for both reports. Different experimental controllers and training runs are retained because they test different conditions; they are not duplicate publication drafts. Modules with identical interpreter, constraint, memory and backend code delegate to `tutor/core/`.

## Inspect results without a model

Python 3.11+ is sufficient for these commands, run from the repository root:

```sh
python -B scripts/check_records.py
python -B -m unittest tutor.rendering.test_rendering tutor.core.test_revision -v
```

The first command executes only authored bounded reference programs, checks exported counts, recorded audits, SQLite integrity and business arithmetic. It does not execute generated model explanations. The second uses tool-only/scripted backends and temporary databases. Neither command downloads weights or contacts a teaching API. Historical audit checksums refer to pre-deidentification source artifacts, not the current repackaged filenames; use the release manifest for current file integrity. The original failed numerical audit remains a failed record beside the separate passing numerical review.

## Regenerate data into a new directory

```sh
python -B synthesis/src/build_data.py --output-dir outputs/data_rebuilt
```

The generator refuses an existing output containing `stats.json`. The eight generated JSONL files (including all 1,000 SFT examples, 500 preference pairs, 36 development examples, 60 bridge references, 100 preference-evaluation pairs and the candidate ledger) were regenerated and matched the published files byte-for-byte. The 24 separately authored natural questions are frozen in `synthesis/dataset/independent_test.jsonl`; they are not randomly generated by this command. The source is deterministic and uses the standard library, not a teacher-LLM call for each example. `synthesis_legacy/` and `data/legacy/` preserve the original comparison's implementation and inputs.

## Optional model training

Training was already performed in the recorded CPU/cloud experiments. No model rerun is required to inspect these findings. Weights, optimizer states and adapters are intentionally excluded from this repository; downloading the pinned base does not restore omitted trained adapters.

```sh
python -m pip install -r requirements-ml.txt
python -B training/prepare_model.py --dest models/base
python -B training/run_cloud.py --model models/base --dataset synthesis/dataset --out outputs/first_cloud
python -B training/run_retry.py --model models/base --dataset synthesis/dataset --out outputs/exploratory_retry
```

The download script verifies the official base snapshot file hashes. The first runner uses last-eight-layer rank-16 Q/V LoRA and SFT learning rate 0.0002; the exploratory retry adapts all 24 layers with SFT learning rate 0.0001. Both use three SFT epochs, development-based epoch selection, 500 DPO updates and a continued-SFT control. They do not have matched response-token or compute budgets. The larger layer scope and learning rate change together, so the retry is not a single-factor ablation. GPU/PyTorch versions and device differences can change numerical behavior. Installation pins describe recorded reference environments; they do not guarantee bitwise reruns on other hardware.

`training/legacy/` preserves the earlier small CPU experiment's implementation. Case IDs, relative paths and serializer labels were renamed for publication, while numeric measurements, model responses and failure judgments were retained. Historical checksums embedded in observations are provenance records; checks in the new retry runner are explicitly re-pinned to packaged inputs and do not retroactively certify historical scripts.

## Tutor and memory

`tutor/legacy/` contains the original two historical batches; `tutor/core/`, `tutor/structured/` and `tutor/fence/` preserve separate controlled pipelines and reviews. `tutor/rendering/` is the isolated final-rendering fix: requesting an exercise while withholding its answer still delivers the exercise. Import `TutoringSystem` or `PromptTutoringSystem` from `tutor.rendering.system`. The wrapper does not change historical cases or model adoption counts. SQL memories use synthetic learner identifiers; caller-ID filtering assumes a trusted caller and is not authentication.

## Business scenarios

```sh
python -B business/model_business.py --output-dir outputs/business_recomputed
```

This reproduces assumptions and arithmetic, not observed demand, revenue or teaching results. The default output is separate from saved experimental records. Vendor pages are dated source claims; full third-party article/webpage copies are not republished.
